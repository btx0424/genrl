# Agent notes

Read this before editing. The README tells a person how to run the project. This file records decisions that the code does not make obvious.

## Current work

Flow matching is the active track. Diffusion uses the same 10 Hz clips, relative rotations, DiT default, and first-frame inpainting. Its sampler is 80-step DDIM.

An in-progress run is `outputs/flow_matching/2026-10-11_21-04-03`. It uses the config as committed for that launch: 10 Hz, relative rotations, first-frame inpainting, linear upsampling, `model_dim` 256. Leave that process alone. Newer upsample choices (`conv_transpose`, `pixel_shuffle`) exist in `TemporalUNet` and are not what that run is training.

The open problem is motion quality. Samples have jittered, and absolute pelvis rotations cartwheeled (about 30° per 10 Hz frame, against about 3° in the data). The relative-rotation change is the attempt to stop that. Judge it from GIFs and from `rot6d/*` plus `consistency/*` on SwanLab, not from the training loss.

## Decisions already made

- Keep the simulator velocities. Do not replace them with finite differences. The consistency metric compares those velocities with a finite difference of position. On 10 Hz smallbox test clips the floor is about 0.011 m/s, 0.182 m/s, and 0.610 rad/s for object, pelvis, and joints. Getting close to that floor is the goal. The metric is not a loss term.
- Flow matching and diffusion train at 10 Hz (`data.sample_hz: 10`, every 5th frame of the 50 Hz clip) and GIFs are linearly stretched back to 50 Hz.
- The first frame is inpainted. It is written into the noisy clip and left out of the loss. Sampling pins a real first frame from the dataset. Do not clamp the prefix only at sample time.
- Pelvis and object rotations in the flow-matching features are relative to that first frame, which is the identity 6D value `[1, 0, 0, 0, 1, 0]`. The absolute frame-0 rotation is an anchor used only when composing the GIF. Yaw is already removed and the first pelvis xy is the origin, so those channels carry no information.
- 6D rotations are not z-scored. Joints, positions, and velocities are, per dimension.
- `rot6d/pelvis` and `rot6d/object` measure the Gram-matrix error of the raw network output on frames after the pinned prefix. Zero means the two columns are orthonormal. `rot6d_real/*` on the data is zero.
- GIFs draw the nearest proper rotation (SVD), not Gram-Schmidt. Gram-Schmidt flips the body when the two columns are nearly parallel.
- Sample from the EMA weights (`ema_decay: 0.999`). Flow-matching time stays in `[0.01, 0.99]` for 80 Euler steps.
- Checkpoints from before a representation or schedule change do not match the current code. Do not resume them. A matching resume is `checkpoint.resume=.../checkpoints/last.pt`.

## Data

`WeavePreInteractionDataset` loads `rollout/<split>/<object>_rollout.npz`, drops clips with no contact-and-speed onset, and drops clips shorter than `duration` (1 second, 50 frames at 50 Hz). Knee and ankle contact is ground contact and does not count. The feature layout is documented at the top of `src/genrl/data/segments.py`.

The robot URDF is `assets/unitree_g1/g1_29dof_rev_1_0_with_inspire_hand_DFQ.urdf`. Joint order in the dataset is not URDF order. Remap by name. The Inspire mimic tags are stripped because the dataset records those joints independently. Meshes are a local symlink, gitignored.

The matching MJCF, `assets/unitree_g1/g1_29dof_rev_1_0_with_inspire_hand_DFQ.xml`, is generated by `scripts/urdf_to_mjcf.py`. It adds `floating_base_joint` (freejoint on `pelvis`), so `qpos = [pelvis xyz, pelvis wxyz, 53 hinges in MJCF order]`. Mimic tags become joint equality constraints there. They only affect dynamics, not `mj_kinematics` replay. Regenerate it instead of hand-editing.

## Useful commands

QGF (`scripts/train_qgf.py`) does not train the flow. It requires `flow=<flow-matching last.pt>`, loads that EMA, and freezes it. The critic is IQL. State and action are both the full normalized feature, normalized with the flow checkpoint's mean and std. The reward is the negative sum of six penalties, each divided by its dataset mean: object linear speed, object position drift, object spin, and position-velocity consistency of the object, pelvis, and joints. At 10 Hz the onset frame is not in the clip, so every frame counts. Rewards are z-scored before the Q target. Each step also draws a batch from the frozen flow, labels it with that reward, and fits Q to it (`iql.generated_steps`, `iql.generated_weight`). V stays on the dataset. Sampling adds `guidance * grad Q` to the velocity (`guidance` is `1/beta`, default 0.1). `object/speed_before_touch` is the metric; `object_real/*` is the data. `checkpoint.resume` resumes the critic only.

Advantage-weighted diffusion (`scripts/train_awd.py`) fine-tunes a diffusion checkpoint. Pass `diffusion=<diffusion last.pt>`. Each step draws clips from the EMA model and uses those as the denoising targets. The noise loss is weighted by `exp(advantage / beta)`, with advantage computed inside that sampled batch. `train/reward` is the mean reward of those samples. The reward is the same six-term penalty as QGF. A frozen copy of the checkpoint is the behavior-cloning target (`bc_weight`). `checkpoint.resume` resumes the fine-tune only.

```bash
uv run python scripts/train_flow_matching.py
uv run python scripts/train_flow_matching.py upsample=pixel_shuffle
uv run python scripts/train_qgf.py flow=outputs/flow_matching/<run>/checkpoints/last.pt
uv run python scripts/eval_qgf.py
uv run python scripts/train_awd.py diffusion=outputs/diffusion-dit/<run>/checkpoints/last.pt
uv run python -m genrl.data.view --split test --objects smallbox
```
